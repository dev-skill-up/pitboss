So the directory to keep is `<RUNNER_TOOL_CACHE>/node/<version>`, which holds both the `x64` tree and its `x64.complete` marker (the context `runner.tool_cache` is that directory's root). In `build-android`, before `actions/setup-node`, the step "Name the Node installation" reads `.nvmrc` into the output `version` (a workflow expression cannot read a file, and setup-node's own `node-version` output exists only after the download; the one line is `echo "version=$(cat "$NVMRC")" >> "$GITHUB_OUTPUT"`), and the step "Restore the Node installation of an earlier job" is `actions/cache/restore` (the commit the downloads cache already uses) of `${{ runner.tool_cache }}/node/<version>` under the exact key `node-tool-cache-<os>-<arch>-<version>`, with no `restore-keys`, since another version is another directory. The last step of the job, "Keep the Node installation", is `actions/cache/save` of the same path and key, run (the default `success()` condition) only when every step before it passed and only on a miss (`cache-hit != 'true'`).
