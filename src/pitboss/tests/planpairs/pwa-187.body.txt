## What

`smoke-test.sh` (written by `create_android`, run by `android.yml` on the emulator) now plays the system font scale. With the text shown it sets `settings put system font_scale` to 1.0, 1.3, 2.0 and back to 1.0, and at each reads the page through the DevTools reader that `keep_dom` already had (`devtools_eval`, now taking the expression): the height of the first line box of the smoke text (a `Range` over its text node, as the page lays it out), the window's width and the page's `scrollWidth`. It fails unless, at 1.3 and 2.0, that line is the 1.0 line times the scale within 10%, the page is no wider than the window and the text lies inside the window. A shell that calls `setTextZoom(100)` keeps the line at its 1.0 height and fails. Rule: `.claude/rules/android-smoke.md`, "The system font scale on the emulator".

Additive: `build_smoke_test_script_font_scale` is the form `create_android` writes; `build_smoke_test_script` keeps its type and, with the font step not in it, its text, and `tests/dynamic/smoke-compat` calls it (its `expected` is that text). It carries a deprecation comment (`android-smoke`, removal bats-lang/pwa#189, p2). The head and tail of the script are shared.

## Process, documentation or CI

- No capability: the step runs on the CI host (adb, python3) and only reads the page (`Runtime.evaluate` of a read-only expression: `getClientRects`, `innerWidth`, `scrollWidth`). No JS is added to the page, the service worker or `MainActivity.java`; nothing the app runs, and nothing pwa generates for the app, changes. Only `smoke-test.sh`, a CI script, differs.
- Why shell and python3, not bats (quire#646): same as pwa#166, the script is generated shell that runs on the emulator host with adb and no bats, and bats has no WebSocket client. The test is shell and python3 for the same reason.
