## How to read this ticket

The coverage table, https://github.com/moshez/claude-jsonl/blob/main/reports/pitboss-corrections-coverage.md, lists 87 rules Moshe has stated, each with the pitboss code that enforces it, the test that covers it and a status. - Rules about slots, workers and briefs: ids B1 to B26.
- Rules about disk, runners, CI and pins: ids C1 to C13.

The plan with the history of why pitboss kept needing corrections is https://github.com/moshez/claude-jsonl/blob/main/reports/pitboss-iteration-plan.md.

A register is a data file, `src/pitboss/rules.tsv`, with one row per rule: id, date, Moshe's words, the function that enforces it, the tests that cover it, and a kind. Kind `enforced` means code refuses or does the thing; `output` means a printed line or command makes the act visible; `outside` means nothing pitboss can print can enforce it (the rule is about Moshe, the coordinator or a product decision).
