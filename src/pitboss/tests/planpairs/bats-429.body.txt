## What changed

* Every reader of `bats.toml` in `src/` is listed below, found by search (raw output in Evidence), and each is whole or reads nothing. Two were not and are fixed here: `bats add` (`do_add`) read 4096 bytes and **wrote them back over the file** (data loss for a longer manifest): it now appends its one line (`append_file_from_builder`, `AppendExisting`) and neither reads nor rewrites the file. `bats remove` (`do_remove`) no longer spawns `sed -i` (bats#445): it reads the manifest whole, copies every line except those naming the package (the quoted name at the start of the line) into a builder and writes it back through `write_settle`; a package that is not there leaves the file untouched and says so. It adds no `run_cmd_capture` call and removes none, so bats#444's list of fifteen call sites (`src/commands.bats:597,616,737,754` among them) is unchanged by this PR.
* `read_toml` / `read_manifest` (`src/helpers.bats`) read whole (`read_whole_m`). The toml package's `parse` copies 65536 bytes and stops after 256 entries without saying so (bats-lang/toml#46): a manifest over 65536 bytes is now `FileTooLarge` (an error), never parsed cut; the 256-entry cut cannot be seen from bats and is stated.
* The ceilings, as they are: a file of 268435455 bytes or more is refused by `whole_of_open` (`z >= 268435455`); a manifest over 65536 bytes by `read_toml`.
* Earlier commits of this PR: `read_unsafe_flag` is the one reader of `unsafe`; `write_with_version` zips the whole manifest; `read_whole` keeps a failed read's own error.
* `.claude/rules/build-freshness.md`: the field table (judged-by cells corrected) and the table of every reader.
* `tests/toml-fields/check.sh`: `bats add` on a manifest of 8767 bytes, `bats remove` of one of two packages, of an absent one, and among look-alikes (a commented `"added"`, a string value holding `"added"`, an indented `"added"` and the real line: only the real line goes, and a second remove says not found; `.claude/rules/build-freshness.md` names `dep_cons` and `pdep_cons`, its greps use `-E` with a plain `|`) (the manifest otherwise byte for byte), manifests of exactly 65536 (read to its last byte) and 65537 bytes (refused), a mangled log name fixed, the why-shell comment corrected.

## Why the test is shell (stated as true)

`tests/toml-fields/check.sh` runs the compiler binary it is given several times over project directories and compares their `build/` trees and logs, as every `tests/*/check.sh` does (`check.yml` loops over them). A test in bats is possible and is not made here: bats has no `tests/static` (that was quire's runner, folded into `bats fixtures`: one snippet in one copy of one project against an error text, no second manifest and no `build/` to compare); `bats test` is a step of no workflow here and no module of the compiler has a `$UNITTEST` block; the runner it builds is given no path to the compiler (the process package could spawn one named by an environment variable, but `spawn` has no working directory, so the test would chdir the runner), and the `build/` trees would be walked and compared in bats. This is not "exhausted": it is a rewrite of the suite's convention, and the ticket for it is filed: bats#446 (p1, port the script to bats).
