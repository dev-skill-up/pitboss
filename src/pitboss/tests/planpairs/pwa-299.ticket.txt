## What happened

quire#1083's `android / build-android` (https://github.com/bats-lang/quire/actions/runs/42581785151/job/129045575664, 2026-11-09 08:00Z) ran `actions/setup-node` with `node-version-file: app/android/.nvmrc` (22.23.3) and, finding no such Node on the runner, did `Acquiring 22.23.3 - x64 from https://github.com/actions/node-versions/releases/download/22.23.3-35947643734/node-22.23.3-linux-x64.tar.gz`, a live github.com release download. In the same run the next step's JDK download from github.com (adoptium's release asset) returned 504 three times and failed the job. The Node download is the same kind of live fetch and would fail the same way in an outage.

## Cause

`setup-node` caches the package manager's store (`package-manager-cache`), not the Node installation: the version it is asked for goes to the runner's tool cache only after a download, and the tool cache does not survive to the next job. Every job whose Node version is not preinstalled on the runner image therefore downloads Node from github.com. The same holds for e2e-setup's Node (`node-version-file`, bats-lang/pwa#136) and for the Node of every job of pwa's and quire's workflows that sets it up.

## Done-when

* `android.yml`'s `build-android` and `smoke-test` jobs restore the Node installation from `actions/cache` (keyed by the version in `.nvmrc`, saved after a passing job) into the runner's tool cache before `actions/setup-node`, so a warm cache makes setup-node find the version and download nothing, and a test pins the restore step as pwa#296 pins its prefix.
