## Plan

Why: quire#1083 adds a step to the `build` job of quire's `check.yml`, whose `on:` block is push, pull_request, merge_group, workflow_dispatch and schedule. The row `scratch-run` of text-lint calls it gated because `schedule` is one of the 21 events, and refuses the pull request until it cites a run of relock-scratch that shows nothing about the change. The `pull_request` run of the pull request itself executes the changed step, which is what #509 asks for.

Done-when of #597, word for word (the ticket has no comments):

* A changed workflow file whose `on:` block holds `pull_request` (or `push`) beside a gated event is not judged by `scratch-run` for the job steps the PR's own `pull_request` run executes; a file whose only triggers are gated events is still refused.
* A test plants quire's real `on:` block (push, pull_request, merge_group, workflow_dispatch, schedule) with a changed step and requires no `scratch-run` finding.
* A test plants a file with only `schedule` and a file with only `pull_request_target` and requires the finding for both.
* `text_lint` prints, for the accepted file, no finding, and for the refused one the file and the trigger that gates it.

One PR: yes. Only `tools/text-lint` changes; no workflow, no `src/` of the compiler, no `bats.lock`, no `bootstrap/c`, and no line is added to any `.md` or `.rst` file.

The change:

- `tools/text-lint/src/gated.bats`: the trigger reading now returns where the matching event's line starts in `gated-triggers.txt` (a negative number for none) instead of a bool; a changed file is gated by the first such event of its patch or its base copy, and is not gated when the same reading with the events `pull_request` and `push` finds one in the patch or the base copy. The file is judged whole, since a line reading cannot tell which job a step is in. A word as a permission, in a step or in a condition is not a trigger, as before; `pull_request_target` is a different word from `pull_request`. The finding is now `PR body: <file> runs from the default branch on its trigger <event>: cite its job URL in bats-lang/relock-scratch (scratch-run)`.
- Fixtures under `tools/text-lint/tests/gated`: the 21 event files and 3 form files had `push` as a decoy beside the gated event, which now exempts them, so the decoy is `workflow_dispatch`; the base `check-gated-list.yml` likewise; the hunk case moves to a new base file `check-hunk.yml`, whose `on:` has no `push`. New: quire's `on:` block with a changed step (`check-quire.yml`, `changes-quire-step.diff`), a new file with schedule and pull_request, and the refused nearest inputs: only schedule, only pull_request_target, only schedule with the words `push` and `pull_request` in permissions, condition and step, and a new file with schedule and pull_request_target.
- `tools/text-lint/src/text_lint_tests.bats`: the expected findings carry the trigger; the status description is cut at 140 characters as before, so it now ends in `bats-lang/re`; two new tests, `test_pull_request_or_push_beside_a_gated_event_is_not_gated` and `test_only_gated_triggers_are_still_refused`.
